## Запуск без Docker

Требуется Node.js 22.12 или новее. В двух терминалах:

```bash
cd backend
npm ci
npm run dev:local
```

```bash
cd frontend
npm ci
VITE_API_ORIGIN=http://localhost:13000 npm run dev -- --host 127.0.0.1 --port 15173
```

Открыть http://localhost:15173. API: http://localhost:13000.
`dev:local` запускает отдельную временную MongoDB, импортирует товары и учебные аккаунты из `.dump`.
При первом запуске скачивается бинарный файл MongoDB. Данные этого режима исчезают после остановки.
Учётные данные учебных аккаунтов описаны в [.dump/README.md](.dump/README.md); используйте их только локально.
Можно зарегистрировать нового пользователя через интерфейс.

Для существующей MongoDB скопируйте `backend/.env.example` в `backend/.env`, задайте `DB_ADDRESS` и выполните `npm run dev` в `backend`.
После перехода с MD5 старые пароли не подходят: для учебной базы повторно импортируйте обновлённую фикстуру пользователей или пересоздайте аккаунты. Существующие данные автоматически не удаляются и не мигрируются.

## Docker

Скопируйте `.env.example` в `.env` внутри `backend` и `frontend`. В backend укажите MongoDB-сервис `mongo` и параметры подключения из `docker-compose.yml`; во frontend — `VITE_API_ORIGIN=http://localhost/api`. Затем `docker compose up -d --build`, импортируйте `.dump` по инструкции и откройте http://localhost.
Порты привязаны к loopback. Docker-сценарий требует работающего Docker. Образы и отдельный тестовый Compose-стек с nginx/MongoDB проверены локально; рабочие базы не использовались.

## Проверки

В `backend`: `npm test`, `npm run build`, `npm run lint`, `npm audit`.
В `frontend`: `npm test`, `npm run build`, `npm run lint`, `npm audit`.

Проверки API используют собственную временную MongoDB. Набор покрывает CSRF, инъекции, права доступа, хранение паролей, ротацию refresh-токенов, очистку HTML, загрузки, пути, ограничения тела запроса и параллельные запросы.

## Принятые ограничения

- API принимает JSON до 100 КБ; страницы ограничены 10 записями; строки и массивы проверяются Joi.
- Общий лимит — 40 запросов за 10 секунд на IP. Неуспешные login/register дополнительно ограничены 20 попытками в минуту. Встроенное хранилище предназначено для одного процесса. Это ограничение нагрузки приложения, а защита от распределённой сетевой атаки требует инфраструктуры.
- Все изменяющие запросы требуют `X-CSRF-Token` и cookies, полученных через `GET /auth/csrf-token`. Refresh и logout выполняются через POST. GET не меняет состояние авторизации.
- Изображения — PNG/JPEG/GIF/WebP от более 2 КБ до 5 МиБ; содержимое декодируется с пределом 16 млн пикселей и перекодируется в PNG. SVG-загрузки запрещены; существующие изображения каталога сохраняются.
- Пароли — bcrypt, не более 72 байт UTF-8. До 10 refresh-сессий на пользователя; токены потребляются атомарно. Выход отзывает все access/refresh-сессии аккаунта через серверную версию сессии, включая токены, выданные параллельным refresh.
- В production задайте независимые `AUTH_ACCESS_TOKEN_SECRET`, `AUTH_REFRESH_TOKEN_SECRET`, `CSRF_SECRET` не короче 32 символов; в production обязательно установите `COOKIE_SECURE=true` и используйте HTTPS. В разработке при отсутствии секретов они генерируются при запуске.
- Access token хранится только в памяти клиента. Refresh token остаётся в HttpOnly cookie; после перезагрузки страницы access token восстанавливается через защищённый refresh. При выходе/смене аккаунта очищаются приватные slices и черновик заказа; старые ответы не могут восстановить сессию. Контакты больше не сохраняются в localStorage.
- Изображения хранятся в пределах `IMAGE_STORAGE_MAX_BYTES` (по умолчанию 256 МиБ суммарно, не более 10000 файлов). Неиспользуемые временные/осиротевшие файлы с генерируемыми именами удаляются через 24 часа; очистка выполняется при старте, каждый час и перед загрузкой. Замена/удаление товара удаляет только управляемый файл без ссылок из БД. При неуспешной записи товара перемещение откатывается. Исходные общие изображения фикстур сохраняются.
- В Compose nginx имеет адрес `172.30.187.10`; только он указан в `TRUSTED_PROXIES`. Для прямого запуска оставьте переменную пустой. При изменении сети нужно синхронно изменить доверенный IP. Заголовкам от произвольных адресов приложение не доверяет.
- Пагинация заказов выполняется в MongoDB до populate. Список клиентов содержит сводные данные и последний заказ, а не всю историю.
